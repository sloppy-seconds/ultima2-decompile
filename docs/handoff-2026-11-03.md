## 1. What closed

**G39 — the rocket, observed end to end.** Owner-played in the noVNC container, then
scripted headless. Evidence: `captures/spice86/g39-rocket-flight`, plus
`g59-grass-landing`, `g60-plate-halt`, `g62-orbit-state`. The sequence is
`B` board → `L` launch to orbit → optionally `H` hyperwarp → `L` dive → unsteerable
southward march → tile verdict. Boarding checks the gate item and does not spend it
(second independent sample, so **G42** closed too).

**The parked-rocket triple, `DS:69/6A/6B`.** This was the best find and it was pure
static work: sweep every reader and writer.

| byte | meaning |
| --- | --- |
| `DS:69` | flag — a rocket stands at the cell below and must be re-staged |
| `DS:6A` | that cell's x |
| `DS:6B` | that cell's y |

Writers: `asm/38B0` on launch (then it saves) and on a survived dive, where **Earth
clears it and off-Earth sets it**. Readers: `asm/080D` on the `P` load path, `asm/0839`,
`asm/245a`, and `asm/3823`'s site-exit block — all stamping `0x50`, the rocket tile.
It lives inside the save record *because* a rocket left on a planet has no authored pad
and the record is the only thing that puts it back.

**Why the launch auto-saves, and why site entry does too.** `asm/38B0` calls the save
body `L_0024fd` directly, bypassing `asm/3DFA`'s `ONLY OUTDOORS!` / `ONLY ON EARTH!`
guards, behind `[DS:6D]==0 AND [DS:4A]==0`. Five more callers of that body turned out to
be **site entries** — `asm/341E`, `asm/343F`, `asm/34B5`/`asm/34CF`, `asm/34E4` — each
recording the return cell then saving. Proven on disk: entering Port Boniface from sector
30 rewrote `player`, and **the sector stored was 30, the one you came from**, which is
the mechanism behind dying in a town and waking outside it. **G64(a) closed.**

**G59 — the survivable landing tile.** The framing was the obstacle. The descent path is
a function of the trajectory alone, so it visits **the same 32 cells in every sector**;
the rule is not "land on grass" but "land on one of the grass cells the march passes
over". Earth has exactly two: `(1,10)` and `(1,12)`. World X's sector 90 has seven. All
derivable statically and nobody had intersected the path with the map.

**G60 — `YOU HAVE EXPLODED!` is a halt, not a death.** With PLATE seeded the message
prints and the game spins on `jmp L_006c77`. HP stayed 9999, `DS:51..59` were **not**
zeroed, and the passive food tick stopped between two samples six seconds apart. The
death tail's signature is the exact opposite. Also: the check is not on the launch path;
a PLATE character launched fine.

**G62 — there is no discriminator byte.** `asm/6999_space_status` **is** the in-space
command loop, entered from exactly one place (`asm/38B0` line 177, `call L_006b99`). It
prints `CMD: `, polls, and dispatches: four arrow scan codes held in `DS:26E..271` to
`LEFT`/`RIGHT`/`CLIMB`/`DIVE`, `H` to `asm/6DFD_hyperwarp_flow`, `L` to
`asm/7030_space_collision`. **There is no `ret` in it at all** — it exits only by jumping
out. The second `L` never reaches `cmd_L`. The state was on the stack.

**New facts, all byte-plus-frame or byte-plus-disk:**

- **World coordinate tables at file offset `0x7212`** (runtime `0x7012`). Located by
  pattern, not arithmetic: exactly one 30-byte run in the binary has `table[0] == 6/6/6`
  and `table[9] == 9/9/9`, which are the two triples read off live screens.
- `XENO/YAKO/ZABO` are `DS:4CA/4CB/4CC`, **derived from the world byte**, not a
  position. Orbit is equality with a triple — no tolerance.
- **World names** `0..8` = EARTH MERCURY VENUS MARS JUPITER SATURN URANUS NEPTUNE PLUTO;
  `9` prints `X` from a routine past `0x729B`; `0x0A` is deep space.
- **Off-course fires iff `(fuel & 3) == 3`** on the post-decrement count, then
  coordinates become `rand & 7`. Confirmed three times on three fuel values. Because the
  roll cannot produce a 9, **X is unreachable by misfortune**.
- **Space needs armour ≥ REFLECT** (`cmp $0x5` on `DS:62`). REFLECT suffices; the meta
  claim "Power Armor required" is wrong on the detail.
- **Landing sector is computed**: Earth → 40, world N → N0, ones digit always forced to
  0, so a rocket always arrives in a wilderness sector. `REQUEST DENIED!` fires only from
  deep space.
- **The descent rule written from bytes before anyone had launched predicted both live
  landings to the cell** — `(7,62)` and `(5,44)`. Strongest static-to-live confirmation in
  the project.
- **CP8's frontier is now `0x729B`**, the highest offset ever executed. `asm/72A0` holds
  `MINAX IS DEAD!!` / `ALL HER WORKS SHALL DIE!` and still has never run.
- **`tlkx92`/`tlkx93`** carry the Antos quest text: `ANTOS IS ON 'X'!`,
  `FIND ANTOS, EARN THE RING!`, `FATHER ANTOS CHANTS: YOU HAVE EARNED MY BLESSING.
  RETURN AND CLAIM THE RING!`. Minax is confirmed in sector 03 on Earth (`tlkx03`).

## 2. Corrections, five of them mine and three made the same day I was corrected

This section exists because the pattern was the same every time: **a mechanism inferred
from plausible prose, then asserted as a consequence.**

1. **`DS:6D` "never changes, so it is not the Earth/space switch."** Wrong, from one
   sample. It moves on hyperwarp, not on launch. I said this out loud mid-session and then
   made the same class of error twice more.
2. **"Death zeroes the stats and that zeroed record is what a later save persists."**
   First half measured, second half invented, and the second half was the load-bearing
   part. The death tail calls only `L_0052f9`; it never calls the save body. Three dead
   runs all still had their seed record intact on disk. **Death is memory-only.** The
   owner caught this, not me.
3. **`YOU HAVE EXPLODED!` implemented as lethality.** Written from the words alone. It is
   a hang. A screenshot would not have caught it, because the screen looks like a death.
   Fixed in `space.c`, and the gate now carries an explicit **non-assertion** explaining
   why it must not assert death.
4. **`docs/save-format.md` § 10 "crossing a site edge writes nothing"** — true for
   `mapx`/`monx`, false for `player`. The original measurement never compared the player
   record to its seed. Corrected in place.
5. **The runtime/file offset direction.** AGENTS says `file_offset = offset + 0x200`. I
   applied it inverted and produced a confident table of impossibilities (Earth reading
   150/160/160). **Filenames are file offsets; labels are runtime.** `L_000e62` is
   `asm/0C62`.
6. **A silence assertion that read stale state.** It checked the vram for `ONE MOMENT
   PLEASE!` and passed because a *previous* command in the same test had echoed it. It
   needed `u2_vram_init()` first. Same class as #3: judging a claim against the wrong
   moment.
7. **An assertion that could not fail.** It expected `sector == 0`; the mutant also
   produced `0`. Caught only because I mutated the code deliberately. Dropped, with a
   comment saying why.

Also corrected: the launch/dive conflation (§ 1, G62), and the phrase "unrecoverable
freeze", which oversold a difference that turned out to be narrower than claimed —
neither death nor the hang damages the save.

## 3. Open, and what actually blocks it

Ranked by what it unblocks.

1. **The engine's nested space loop.** Now fully specified and unblocked. `launch_rocket`
   needs: launch → enter a space loop (readout, `CMD: `, arrows, `H`, `L`) → break into
   the descent on `L`. Not a flag, not two handlers. **This is the single largest
   remaining fidelity gap in the rocket**, and it is the reason the dive-branch behaviour
   currently runs at the wrong moment. See `asm/6999_space_status`'s header for the
   dispatch.
2. **Live confirmation of the parked-rocket restage.** Dive onto grass on **world X**
   (seven viable cells in sector 90), survive, restart, load, and check the grid
   re-stages `0x50` at the landing cell. This would exercise the **off-Earth dive branch**
   for the first time in anything — right now it is bytes-only. Agent-drivable; the timed
   dive already works (§ 4).
3. **G61 — does Antos's ring gate Minax?** The shipped text describes a chain (find
   Antos in sector 93 → blessing → ring, `items_held[0]` at `DS:D6`). Nothing yet shows
   the ring being *required* to reach or kill Minax, and `asm/1040` does not read it.
   **This is CP8's real question.** CP8 has no victory condition implemented.
4. **G64(b) — do time doors also auto-save?** Owner states yes. **`recalled`, not
   found.** The five unexplained save-body callers turned out to be site entries, not time
   doors, and `docs/moongates.md` evidences no transition save. Needs the rotation
   routine decoded (`asm/2708`–`2775` was refuted) or a live crossing with a `player`
   diff either side.
5. **`asm/6CC4` is still an unnamed bulk-wave stub** headed *"behavior not yet reviewed"*
   — and it holds `L_006ec4`, the routine every space arm calls, shared with the
   hyperwarp flow and `asm/7030`. It is the actual space-movement routine. Read it and
   name it.
6. **`asm/245a`'s caller is unknown.** Its *what* is settled; its *who* is not, and its
   header says so. Same shape `cmd_I`/`cmd_D`/`cmd_K` had before the Phase 2 map was
   re-cut.
7. **G63 — owner decision.** The rocket can only land in a handful of cells per world,
   two on Earth. Surface it in the UI or stay faithful and silent? The original gives no
   help.
8. **Enhanced mode and save slots — owner decision.** The engine auto-saves faithfully in
   both modes. Whether to soften that, or do the better thing and add multiple slots, is
   unmade. The hook point is `u2_overworld_autosave`, deliberately in one place.
9. **`tools/save_cross_load.py` has not been re-run.** Deliberate: the record layout is
   byte-identical, since `reserved_67` already spanned those offsets, and the disk-offset
   assertion in `save_q_check` is the proof. **If you touch save handling further, run
   it** — it needs `original/` and `references/` and is not in CI.

## 4. Techniques that cost time. Use these.

- **Harvest before teardown, always.** `bash deploy/spice86-novnc/dump.sh 20190` **before**
  `up.sh --down`. The container does no dump on teardown and headless Spice86 ignores
  SIGTERM, so the trace is simply gone. Run 1 of this capture lost its trace this way.
- **Scripted driving goes headless, never in the noVNC container.**
  `tools/spice86_start.sh --headless --patch-arrows --player FILE --name LABEL`, then
  `tools/spice86_type.py --keys Escape,p`. It also harvests correctly.
- **Find fields by diff, not by guessing offsets.** Dump the whole DS block before and
  after the event and diff. That is how `DS:4CA/4CB/4CC` was located and how the orbit
  scratch was ruled *out*. A 320-byte dump missed the coordinates entirely; 4096 found
  them.
- **Locate tables by pattern, not by arithmetic.** Search the binary for the constraint
  the live observation gave you. Two independent observations pinned a 30-byte table and
  it had exactly one match.
- **Controlled A/B beats a single observation.** Launch from sector 40 vs 41; site entry
  vs no site entry. Same character, same actions, one variable. Both auto-save findings
  came from this and each took minutes.
- **Mutate your gate before trusting it.** Force `save_body` to write a constant, confirm
  red, revert. It found one assertion that could not fail. Write the failing control from
  the same directory and ref position CI will use.
- **Timed input in-process.** Import `Mcp` and `send_key` from `tools/spice86_type.py`
  rather than spawning it per attempt — the grass window is ~330 ms and a process spawn
  eats it. Poll `DS:00/01` over the HTTP API in the same loop.
- **Refresh provenance after every harvest.** `python3 tools/cmd_handlers.py
  --write-provenance`. It moved 209 → 210 → 212 → 214 today and each time it turned
  `check_all` red. It refuses to touch verdict prose, which is correct.

## 5. Hazards, each of which cost something

- **Injecting keys into the `spice86-novnc` container crashes Spice86** (SIGABRT, core
  dump). Documented in `handoff-2026-10-29b.md` § 5. Memory reads are safe. I hit this
  anyway because I was writing a new driver and did not check.
- **`tools/turn_recorder.py` does not work against the container.** It requests
  `/api/memory/<phys>/range/<n>`, which that path does not expose — 404. Use the HTTP API
  directly or `spice86_type.py --peek`.
- **`pkill -f PATTERN` matches your own shell** when the pattern appears in the command
  line you are running. It killed my shell twice (exit 143). Resolve PIDs in one call,
  kill in the next.
- **The `ctx_execute` shell wrapper mangles `for … do` loops** — `NODE_OPTIONS` gets
  prefixed onto the `for` and bash reports a syntax error. Use Python for anything with a
  loop.
- **`engine build fresh` needs `make -C engine clean` first.** Running `make test` leaves
  artifacts and turns that gate red. Not a regression.
- **`git commit -F - <<MSG` chained with `&&` can swallow the next heredoc.** One commit
  per call. Also: a multi-line `edit` whose `oldText` stops mid-sentence leaves an orphan
  tail — verify by reading the specific text back, never a line count.
- **A trace window is not the whole session.** The g39b dump was taken at 15:36:51 and the
  dive landed at 15:43, so the landing path and the death tail are **not** in it. I nearly
  cited that trace as proof of the landing arithmetic. Check timestamps before you claim
  "traced".
- **`DS:13` is `0x78` on foot, not zero.** It is not "mode with a blank default"; the
  vehicle values overwrite whatever walking leaves there. And per G41 it is
  class-dependent (`0x78 + 2*pclass`), so a Mage reads `0x7A`.
- **`asm/72A0` renders the ending text as `db` blobs** marked *"split: branch target
  inside data"*, and `L_00737a` has no label in it. The `MINAX IS DEAD!!` bytes are
  solid; the control flow around them is not decoded. Treat it like `asm/4C50`, which
  renders a string table as invented instructions and is not trustworthy as code.
