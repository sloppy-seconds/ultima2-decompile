## 1. The one thing to do next, and the decision inside it

**The engine has no command loop.** `engine/src/game/game.c` says so in its own header: the
command loop, the overworld and the rest hang off title-flow choices that are currently
stubs. That single gap is upstream of almost everything else that is ready:

| ready thing | blocked on |
| --- | --- |
| era / time-period display (fully solved, see § 3) | command loop |
| speed wiring (model built and tested, see § 4) | command loop — the key-waits live there |
| CP6 towns and NPCs | command loop + the `tlkx` high-bit masking in the extractor |
| CP7 time travel and space | command loop |

**The decision, which is the owner's and was not made this session.** `tools/cmd_handlers.py`
crosswalks all 26 command letters against the jump table and against the capture corpus, and
it is a gate: it exits non-zero when the table, the filenames and the provenance lines
disagree. Of the 26, **14 have execution evidence from captures and 12 have never been
observed running** — the twelve are `C D H J M N O S T V W Y` (`--` in the `exec` column of
`python3 tools/cmd_handlers.py`). So building the loop means choosing:

- **all 26**, marking the 12 as static-inference-only, or
- **the 14 observed ones**, stubbing the rest and leaving a visible gap.

Neither is wrong. The second is more honest about evidence; the first is more useful as a
playable spine. Ask before starting, because a stub that looks implemented is worse than a
gap that says what it is.

`docs/phase4-plan.md` § CP6 is the acceptance model: the gate is the owner playing a full
town session. That means command-loop work has slow, human feedback. That is a reason to
schedule it deliberately, not a reason to avoid it — see § 7.

## 2. What this session actually changed

### Gates stopped being decorative

The prompt that started it: *what is the weakest part of the claim that these gates are
trustworthy?* The answer was two of them, and both were true.

- **`asm_body_guard` could not fail in CI.** It compared the working tree to `HEAD`; CI
  checks out a clean tree, so it compared `HEAD` to itself and could only ever print
  `conserved`. A committed, unmarked body edit passed. Demonstrated before fixing, and the
  demonstration is now control 5 of the selftest.
- **It also could not fail in CP0.** `run_cp0.sh` invokes it from `engine/`, where there is
  no `asm/`. It found zero files, printed `conserved (0 lines, 0 -> 0 files)`, and CP0
  reported that as a PASS. Independent of the first bug, pre-existing, invisible until the
  first fix made the counts print.

Fixes: `--base REF` on the guard, `exit 2` when CI has no real base or when it finds no
`asm/`, repo-root resolution, `tools/ci_base.sh` shared by the workflows, and a new
`gate-suite.yml` running `check_all.sh --ci` plus the guard's controls. `--ci` turns an
unexplained skip of a **required** gate into a failure; gates whose inputs are gitignored by
policy declare themselves with `SKIP*` instead of silently passing.

`engine/tests/asm_body_guard_selftest.sh` is the thing to trust: **10 controls**, all
proven to go red, all run in CI. Read it before changing the guard.

### The body-correction path

`asm_body_guard` went from "no body edits" to "no **unmarked** body edits". A file may change
body only with a header line:

```
# body corrected: YYYY-MM-DD -- evidence: <what proved the old decode wrong>
```

The guard polices authorship; `assemble_clean.sh` remains the authority on truth. A marked
correction that changes any byte still fails the byte match, so the exception cannot smuggle
in a semantic change. Merging and splitting still need no marker.

Nine corrections landed: `asm/353D` (the one that hid G14) and eight title/menu files whose
`movb $N,0x2f` colour writes had been cut in half, with the tail decoded as
`push %es` / `das` / `add %al,(%mem)`. Body lines 26,080 → 26,045.

### Merges: three done, the campaign stopped on purpose

`tools/merge_fragments.py` does a merge as one command, including the `function-map.tsv`

`2199..21FB` (step gate), `06ED..0710` (speed rescaler), `50F9..51A4` (status-line printer).

## 3. Facts worth knowing cold (all of them live in `asm/` headers; this is a map, not a copy)

- **`function-map.tsv` is a tiling of discovered *starts*, not a list of routines.** A row
  means "entry point here, region ends at the next start". Routine truth lives in `asm/`
  headers. Full explanation: `disasm/phase2-summary.md` § "What a row in
  `function-map.tsv` actually means". An agent who reads the filename literally will go
  hunting a defect that is not there; one did, and it cost a merge campaign.
- **The map and the `asm/` file set cannot diverge.** `check_func` validates a file's body
  against its map row. A map-only "fix" is impossible; merging is the only route.
- **gas re-encodes many 16-bit instructions differently from the original.** `mov %bx,%di`
  comes out `89 df` where the binary has `8b fb`. This is *why* forced-keeps exist. A
  correction therefore keeps some bytes as `.byte` with the true mnemonic in a comment.
  Anyone who expects a corrected file to be all mnemonics will break the byte proof.
- **`DS:74` is speed, and its measured value sits above the F7 ceiling.** See
  `asm/06AC_clock_tick_wait` and `asm/4FA5_speed_faster_f7`. The clamp guards the key
  handler, never the startup write.
- **The 20 delay slots are key-wait timeouts, not animation delays.** The tell is
  `cmp $0xff,%ah` after the wait. Slot-to-caller map in `asm/0711_speed_delay_lookup`.
- **Labels are body.** Renaming a file is free; editing `sub_xxxx:` is not. This is the most
  frequently repeated mistake against this tree.

## 7. Hazards. Every one of these cost real minutes this session.

1. **A gate that cannot go red is worse than a tool that lies.** Two of this project's gates
   had never once been capable of failing where it counted. When you add or modify a gate,
   **write the control that makes it red first, and run that control from the same directory
   and ref position CI will use.** A control run from a comfortable place proves nothing —
   and the author of that rule then shipped a control that only worked locally.
2. **Four tools this session returned confident wrong answers because of a bug in the
   checker, not the checked.** A missing `re.M` made the audit report a clean bill of health
   for 290 files including the one known-true case. A guard selftest ran the worktree's copy
   of the guard, i.e. the old code. A `case *"0 lines"*` pattern matched `26080 lines`. A
   substring test for "did the gate do nothing" is not a test of whether it did nothing.
   **Every one was caught by a control built from something already proven true, never by
   looking at the output and nodding.**
3. **Negative claims need the right pattern.** "No writer exists for `DS:554`" and "the era
   index is not the sector digit" were both grep artefacts. Verify a negative with the
   indexed, the relative-displacement, and the plain forms before asserting it.
4. **A mis-decode can hide a read rather than erase it.** Every grep for `DS:49` was correct
   and the corpus was wrong, so the negative result looked earned for a week.
5. **`--tsv` without `--all` silently drops the probable grade.** Check counts after
   regenerating any generated file.
6. **`check_func` validates against the map, not the other way round.** A merged file without
   a map update fails on length, which looks like a byte failure and is not.
7. **Merging is not concatenation when seam labels collide.** `clean_wave.py` numbers repeated
   seams *within* a function, so collisions only appear *across* fragments.
   `tools/merge_fragments.py` refuses on them rather than working around them; that needs an
   owner ruling, and it stopped mattering once the merge campaign stopped.
8. **Do not report a push as verified before the run finishes.** It happened once here, and
   the run had already failed.
9. **`ctx_execute` `timeout` is in milliseconds.** 480 means 480 ms.
10. **Scratch goes in `/var/tmp`, never `/tmp`** (tmpfs, i.e. RAM taken from the model).
