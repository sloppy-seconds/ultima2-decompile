**Hard rule for both:** in `asm/`, only the filename and `#` comment lines may change. Labels

comment — `check_func.py` reads label references out of `#` lines and fails the proof.

### Rename 1 — `asm/4A1C_char_out.asm` → `asm/4A1C_screen_clear_mode1.asm`

The routine is six bytes, `push ax ; mov $0x1,%ax ; int $0x10`, with **no `ret`**, falling
through into `asm/4A22_sub_4a22.asm`, which zeroes the text cursor at `DS:2E/2F` and calls
`L_0053fd`. `mov $0x1,%ax` sets AX to `0x0001`: **AH=00 set video mode, AL=01 = 320x200
4-col graphics**. Not AH=01 as the header claimed, and not AH=0E teletype, which is what real
BIOS teletype is. Read together with `4A22` it is a screen-clear / mode-set prologue, and
that is how `cmd_Z` uses it — the first act of drawing the status page.

The engine built on the wrong name. Every site, verified 2026-10-28:

| --- | --- | --- |
| `engine/src/platform/platform.h` | 13 | seam map: `char_out asm/4A1C_char_out.asm -> seam_char_out -> renderer->cell` |
| `engine/src/core/seam.h` | 14–15 | `/* seam: char_out (asm/4A1C_char_out.asm) — teletype one character. */` + the prototype |
| `engine/src/core/seam.c` | 77–81 | body traces `"char_out", "4A1C"` and calls `u2_vram_put()` |

**The part that is not a rename.** `seam_char_out`'s behaviour — put one glyph at the cursor
with no CR and no margin policy — is a real and useful primitive, and `u2_vram_put`
implements it correctly. What is false is that it has a counterpart at `4A1C`. **The actual
INT 10h AH=0E teletype site in this binary has never been located.** So the seam is
engine-authored, not a mapped original routine.

Two ways to finish, owner has not chosen between them:

- **(a) minimal** — rename the asm file, and re-document `seam_char_out` / `u2_vram_put` as an
  engine primitive with no located original counterpart. Keeps the seam, kills the false
  provenance. Lowest risk.
- **(b) fold it away** — point `creation.c:231` at `seam_char_print` and delete
  `seam_char_out`. Fewer seams, but **not proven equivalent**: `char_print` applies CR
  handling, the right-margin wrap and `text_sync_cursor`, `char_out` does none of that. For
  padding spaces it is probably identical and probably unobservable, which is not a proof.

Recommend (a) unless the owner wants fewer seams on principle. If (b), run the CP1 creation
gates and diff the rendered name field before and after.

### Rename 2 — `state.h`'s `tile_offsector` at `DS:12` → `view_mode`

Not a tile and not an off-sector tile source. It is a **mode byte**: `0xFF` on the world map,
`4` in an interior sector. Written by `asm/0C1F` / `asm/0C2B` on the `DS:4A` branch (`DS:4A`
is the sector's low decimal digit). Its only readers are `asm/5AB1_view_origin_by_mode` and
`asm/5AF9`, and `5AB1` is the routine the monster spawner's arms call — `DS:12 == 0xFF` is how
it decides whether the viewport origin wraps (`and $0x3f`). Live: `0xFF` in sector 20, `4` in
sector 32. `view_mode` is proposed because the byte selects how the view origin is computed.
