## The open queue, ordered by what it unblocks

### 1. Pin the spawn selector — **DONE 2026-10-28, `docs/monster-spawn.md` § 15.4**

Closed by forcing the input instead of waiting for it. `tools/spice86_type.py` grew `--poke`
and `--peek`, `DS:60` was set to `N-1` per command so the chain had to see `N`, and the arms
were trapped at their **entries** rather than their stamp sites — the entry fires whatever the
terrain comparison decides, which is what made the rare arms reachable. All nine arms
accounted for, including the discriminating chain value `0x12` where two bits are set and the
lowest wins. A second finding came out of walking the store site: the byte the arms compare is
the **terrain tile** of the rolled coordinate, not a drawn kind, and the two arms wanting
`0x00` are the two sea creatures.

**Implemented 2026-10-28** as `u2_monsters_wander()` in `engine/src/game/monsters.c`, called
from `creature_turn()` behind the sector-digit gate. `engine/tests/wander_check.c` covers it
with 1633 checks: the arm table for all 256 selector values, each arm driven once on terrain
that suits it and once on terrain that does not, the rollback, the free-slot order, and the
residue a refused attempt leaves in `mon_x`/`mon_y`/`mon_kind`. CP5 W9's H.P. moved from 9980
to 9988 because sector 00 is a world sector and now sees spawns; its assertion is "below the
seed" and still holds.

### 2. Confirm one completed unlock — **DONE 2026-10-28, `docs/needs-gameplay.md` G30**

Both predictions held: the door cell came back `0x0C` (the forest the player stood on) and
`DS:65` went `0x20` -> `0x19`. The reason every earlier attempt refused was **not** the axis:
`cmd_U`'s direction prompt polls for an extended scancode with a bounded counter, and a
one-second gap between `U` and the arrow lets it time out and print `PASS`. Send the pair as
one burst (`--keys U,Right --delay 0.05`). Still open in that item: whether an opened cell
survives leaving and re-entering the sector.

### 3. The Z screen — **DONE 2026-10-28, `docs/status-screen-z.md` § 7**

The layout was derived from the bytes with `objdump` synchronised on every `str_out` site,
which the bulk wave could not do, and `u2_status_draw_full()` now draws the page from it in
`engine/src/game/status.c`, wired to `case 'Z'` in `overworld.c`. `status_check.c` asserts
every field at its derived column and row — 44 checks with the name pool, 39 without.

Three real bugs came out of the test rather than out of reading: `DS:31 = 0x26` is the right
margin and without it `TORCHES-` wraps onto the ARMOUR row; the item list starts at index 0
while the other three start at 1; and the plural `S` and the dash are two prints with only
the plural conditional.

The thing that looked like a blocker was not one. CI cannot have the game, so CI cannot check
game text — it checks structure, and the dev box checks names. The extractor emits the pool
tables when it has the exe and warns-and-omits when it does not; `status.c` compiles either
way; the test asserts which mode ran so a silently lost pool cannot pass as green. That
settled the same way as the existing CP1/CP2 exe-only skips.

`state.h` gained `owned_armour` at `DS:80` (retiring the CANDIDATE note on `reserved_80`) and
`spell_counts` at `DS:B6`.

### 4. CP5 C3 — **DONE 2026-10-28**

Paralysis is a movement rejection: `asm/2520` tests `DS:26B` inside the passability routine
and on the set path prints `--PARALIZED!` and takes the same reject return an impassable tile
uses, so the engine rejects the step the same way.

The prerequisite named below turned out not to exist, which is worth recording because it was
the wrong question. No state seam was needed: certain monsters cast paralysis during combat
(the owner's point, and `asm/0AD3` proves it — `0x34` legs, `0x38` arms, `0xF8` magic
missile, `0x3C` sleep), so the gate seeds a Daemon in the fight and lets the special land
the way play does. The gate ships with a control — the same script against a plain melee Orc
must not print the word — because a gate that cannot fail is the failure mode this project
has been bitten by twice.

The ordering caveat stands as inferred: the paralysis check precedes the terrain test because
that is the address order inside the routine, so a paralysed player facing a mountain gets
`--PARALIZED!`. Never observed live.

## Hazards that cost time this session

1. **`pkill -f PATTERN` kills your own shell.** The pattern matches the invoking
   `bash -c` command line, so the tool call dies with 143 and nothing you queued runs. Hit
   three times. Use `pgrep` + kill by PID, or `$!`, and never a pattern that appears in your
   own command.
2. **An incremental `make` during a bisect manufactures a regression.** Bisecting blamed the
   `--debug-limit` commit for an SDL hang; each step reused objects built against a different
   `u2_ctx` layout. A clean rebuild is clean at every commit. `make clean` before believing a
   bisect that spans a header change.
3. **Opening the RSP/gdb port halts the guest and it stays halted.** `/api/status` then says
   `isCpuRunning: true` with a frozen cycle count and every key is swallowed. `bp_read` now
   resumes on every exit path; anything else you write must too.
4. **On a halted target the monitor reply lags the command.** Sent one at a time, every reply
   is attributed to the wrong command and decodes cleanly — a register dump came back labelled
   `callStack`. `collect_monitors` fires the batch and files packets by content.
5. **`--post-dump` cannot attribute a result to a stop.** Half a second of game time contains
   other spawn attempts, so a stamped slot in the post window may belong to a different
   command. Two apparent Orc stamps dissolved once the pre-increment offset was counted (the
   chain sees `DS:60` *after* the `incb`; a stop at `0CEE` reads one less).
6. **A check that cannot fail looks exactly like one that can.** The first "the order matters"
   unlock check still passed with the order deliberately swapped. Mutation-test every new
   check; if swapping the implementation does not turn it red, the check is decoration.
7. **`check_func.py` reads label references out of `#` comment lines.** A header quoting an
   uppercase `L_005CB1` fails the proof with "not defined in this file". Quote labels in
   lowercase hex, or as `0x5CB1`. Recorded in `docs/asm-style.md` § 8.
8. **`breakCsIp` is multi-shot and cannot be removed.** One arm keeps firing after resumes, so
   a selftest trap poisons a run, and re-arming the same address stacks duplicates.
9. **A probe whose answer key is a return address has no answer key on jump-dispatched code.**
   It returns a plausible zero rather than an error. This is what item 1 turned out to be.
10. **The engine's `--play-map` entry could not be made to load sector 20 from `original/`**
    from the project directory; a copied writable mirror at `/var/tmp/u2/content` works. The
    container path works, so this is probably invocation, not an engine defect — unresolved,
    and it cost real time.
11. **Diffing a mutable state array for "something new appeared" needs a baseline filter, or it
    invents spawns.** The monster slot's terrain byte mutates during a creature's own turn, so
    comparing whole slot records flags a *moving* monster as a new spawn and reported a false
    Orc against the Daemon row. Count only slots that were empty in the baseline, and prefer a
    trap at the branch entry to an outcome census when the outcome can be refused.
12. **A killed breakpoint client leaves the trap set in a state where the next `arm` fails
    outright**, and a trap left armed with no listener halts the guest mid-experiment with the
    status endpoint still reporting it running. Restart the emulator between trap groups
    rather than trying to clean up; `breakCsIp` cannot be removed.

## Rules that bit, so they do not have to bite again

* **Extend the tool, do not write a second one.** `bp_read` grew `--state --ret --stack
  --samples --post-dump` instead of a parallel probe, and that is the whole reason the null
  result was believable rather than suspicious.
* **An owner report outranks an agent inference — but a measurement can also be
  over-generalised.** The night handoff's "proven: the sector does not change on foot" was a
  correct measurement of two digit-0 sectors, generalised past what it showed. Say what was
  measured, not what it implies.
* **A wrong name is worse than no name.** Two misnamed routines were found this session
  (`4A1C_char_out`, `5AB1_sub_5ab1`). One was already named and got `NAME DISPUTED` rather
  than a silent rename; the unnamed one got renamed with the evidence in the header.
* **Two hand-kept copies of a verdict will drift.** The packed-decimal row in
  `phase4-state.md` sat "open, needs the owner's eyes" a day after `status.h` resolved it.
  When you settle something, delete the stale claim rather than reconciling it.
* **Do not commit** `original/`, `references/`, `captures/`, `decompiled/`, `tmp/`,
  `tools/spice86/`, `tools/reko/`, `deploy/novnc/u2-sdl`. All gitignored for a reason.
