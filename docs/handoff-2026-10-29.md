## 2. The corrections. Four of these were written by this project days ago.

**`cmd_T`'s ray is not one cell, and my G35 blocker was an artifact.** `asm/4050_cmd_T.asm` opened
with "aim a ray one cell from the player". The owner bought a horse with the player at (48,53) and
the vendor on the `0x68` marker at (48,51), the shop's sign lettering at y=52 between them — **you
buy across the shop window, not next to the vendor.** The adjacency blocker I recorded the same week
came from comparing raw `mapx` tile bytes against the stamped grid at `DS:1800` as if they were one
representation. They are not: the same ground is `0x0c` in `mapx21` and `0x70` in the grid. **G35 is
unblocked, not blocked harder.**

**`cmd_Y`'s "unresolved fall-through" was a complete routine.** `asm/4542` falls into
`asm/4551..4567`, which is a freeform read-echo loop terminated by Enter — scattered by the Phase 3
cut into seven fragments each headed "behavior not yet reviewed", so nobody read the range. The
2026-10-25 capture's observation ("letters accumulated and never dispatched") was exact; the
interpretation was backwards. Nothing in `4542..4567` writes memory, so the yell is display-only.

**A failed cast still spends the spell.** `asm/3139`'s gate 5 (the packed-decimal decrement) runs
before gate 6 (`DS:4A >= 4`). Outdoors, `C` printed `CAST-LIGHT-FAILED!` and the LIGHT count went
9 → 8. The natural implementation — validate location, then spend — is wrong, and only a test that
counts stock catches it.

**Our own tool had the class names wrong, twice over.** `tools/u2_edit.py` said `{1: mage,
2: paladin}`; `asm/080D` said "mage"/"bishop". The pool (`asm/4C55_name_pool.asm` pool[72..75]) is
**FIGHTER, CLERIC, WIZARD, THIEF**. "Paladin" is a Ultima III class that does not exist in this
binary. Not cosmetic: the wrong names invert which class is which.

**The on-foot stamp was a constant that was right for the only class anyone tested.** `asm/080D`
computes `0x78 + 2*pclass`; the engine hardcoded `0x78` at world open, so cleric/wizard/thief
entered the world stamped wrong. It hid because a Fighter's stamp *is* `0x78` and every fixture was
a Fighter — the path was not untested, it was tested thousands of times against the one input that
could not tell the two apart. Fixed and gated (`tests/foot_stamp.py`, CP5 V5); CP2 unaffected.

**`asm/20AB` does not price everything, and my first simulation of it was wrong.** Horse 32 gp is
exactly its output at `caller_AL=4`; axe 25 gp is unreachable at any index or stat pair, so the
weapons shoppe has a separate price path. The first simulation let DAA's auxiliary nibble fixup feed
the second `adc` and produced `4, 8, 112, 220` — wrong from the third term and plausible enough to
quote. The corrected model reproduces the header's own anchor (`AL=3 → DI=3 → 0020`), and the
wiki's 52 gp grocery max and 576 gp KILL both land in the sequence at DI=5 and DI=10.

**`DS:26` is aliased.** `moved_flag` in the overworld, the light counter inside a site (`asm/1151`
decrements it; LIGHT writes `0x96`). Torches and the LIGHT spell share **one** counter, so LIGHT is
not a parallel light source. Same mode-dependent reuse as `DS:49`/`DS:4A`.

**Process note, kept because it is the session's theme.** One commit message claimed
`harness-portability` had gained a lesson; the file was staged but never edited, so the message
described a change that was not in the diff. Fixed in a follow-up commit rather than by rewriting
pushed history. A plausible statement that did not land is the exact failure this project keeps
documenting, and it happened here.

## 4. Facts worth knowing cold

- **The sector's ones digit IS the site kind**: 0 wilderness, 1 village, 2 town, 3 castle, 4 tower,
  5 dungeon. `site_enter` sets it. So sector 21 is continent 2's *village*, 22 its *town*, 24 its
  *tower*. The tens digit is the world byte — and that is the unresolved **G45** collision with the
  era index in `asm/3546`.
- **Sector 20 gates**: town (36,29), village (38,46), tower (24,40).
- **Vendors are `mon_type` 0x68 (Merchant) standing on `0x68` marker cells.** Same value, both axes.
- **The stamped grid at `DS:1800` is not the raw `mapx` bytes.** Never compare them.
- **Spell model**: `DS:63` readied slot, `DS:B6[1..9]` stock (packed decimal, consumable),
  `DS:D7 + DS:D8` = WAND + STAFF gate, `DS:4A >= 4` = tower-or-dungeon gate. Pool 36..45 = NONE,
  LIGHT, DOWN LADDER, UP LADDER, PASSWALL, SURFACE, PRAYER, MAGIC MISSILE, BLINK, KILL.
- **Two catalogues, one spell list.** Cleric shrine sells 1–6 = LIGHT, L.D., L.U., PASS, SURFACE,
  PRAYER; magic shoppe sells LIGHT, L.D., L.U., M.M., BLINK, KILL.
- **Prices observed**: horse 32 gp, axe 25 gp, at INT 40 / CHA 40.
- **Class bonuses** (creation.c, byte-cited): FIGHTER +15 STR, CLERIC +10 WIS, WIZARD +10 INT,
  THIEF +10 AGI; **STAMINA gets nothing** from sex, race or class.
- **Project containers run ROOTLESS** (`podman`, no sudo). `sudo podman` is only for root's services.
- `tools/cmd_handlers.py` is the authority for handler evidence. **Never hardcode its numbers in
  prose** — `phase4-state.md` had stale counts twice and now points at the tool.

## 6. Hazards. Each of these cost minutes this session.

- **`--dump-each` prints a frame only when the screen changes.** Fifteen identical refusals are not
  fifteen lines. Counting a word in stdout measures the renderer, not the rule — assert on DS.
- **The CMD window scrolls.** A prompt printed early is gone by the end of the run; assert on it in a
  run that stops there.
- **A dungeon frame is only evidence after a move that landed.** Two frames showed a stale
  `IT'S DARK!` after an illegal arrow and an `ADVANCE-BLOCKED!` and both looked like a failed spell.
- **Arrows need `--patch-arrows`.** Without it every arrow is `-ILLEGAL COMMAND!` and looks like the
  game ignoring you.
- **`setpos` into a site sector wedges the player.** Enter from the wilderness gate cell and press `E`
  in game; the entry routine records the return point.
- **The script input swallows whitespace-only lines** (`strtok`), so a typed space must be `SP`.
- **Adding captures grows the corpus and stale-ages 26 headers.** Run
  `python3 tools/cmd_handlers.py --write-provenance` after any harvest, or `check_all` goes red.
- **`captures/` is gitignored.** A finding that lives only in a capture README is not in the repo —
  it has to land in `asm/` headers or `docs/` in the same commit.
- **Never write a commit message describing a file you did not edit.** See § 2's last item.
