## 2. Corrections made along the way, including two of my own from the same day

- **`adc 0x2,%al` is not "+2".** In the listing dialect an operand with no `$` is a **memory** read,
  so the CAST target scan aims at `DS:00 + DS:02`, not two cells east. `DS:02/03` are a **signed
  facing delta** — `(01,00)` on entering a tower, `(00,FF)` after one Left turn, unchanged by Down.
  MAGIC MISSILE hits the creature you are facing. My "two east, three south" was self-refuting on
  the site grid's parity and I quoted it before running that check. Recorded as a TRAP in
  `asm/330C_cast_target_finder.asm` and as a generic lesson in `docs/harness-portability.md` § 6.
- **`mon_kind` is not a floor index**, which is what `asm/330C` had inferred earlier the same day. The
  tower's floor-0 creatures carry kinds 0..15 at once and `monx24` is all zeros, so the CAST gate is
  literally "kind index == caster's floor number". Refuted in that header, with the live flip.
- **`cmd_D`'s gate was mislabelled** "the key byte" at `DS:4A`; it is the site kind, so `cmp $4/$5`
  means DESCEND works in a tower or a dungeon. The stale inline comment is on a body line and stays;
  the correction is in the header.
- **`asm/2626`'s verdict block was labelled with file offsets and called runtime.** Real runtime is
  `0x2651..0x2662`. The execution dump is what showed it.
- **The ladder arms are swapped between tower and dungeon** — in a dungeon DOWN and UP move the floor
  counter the opposite way. Byte reading, not observation; dungeons stay parked.
- **`asm/1451` renamed** to `site_cell_open_on_floor`: it reads the cell at `DS:23/24` on the floor in
  `AL` and callers fail on `jne`, so it answers "is that cell open?", not "does it exist". That is why
  UP LADDER fails at the tower entry cell and works one column over.

## 4. Techniques that cost time. Use these.

- **Hold a value the game keeps overwriting.** The site tick rewrites `mon_x/mon_y` and the walk loop
  rewrites the cursor, so a poke followed by a key loses. Import the tool instead of spawning it:
  `sys.path.insert(0,"tools"); import spice86_type as st`, one `st.Mcp()`, and `st.write_mem` in a
  loop — ~2 200 writes/s, enough that the value is still there when the handler reads it. Confirm
  with a `bp_read` stop **at the routine's entry**, which is the only way to know what a scan saw.
- **`T` + direction at a 50 ms gap**, from a cell the foot ladder admits exactly one step from a
  merchant on a `0x68` marker. Everything else about headless transacting is a red herring.
- **Path over `mapxNN` with `foot_ladder`, never over the stamped grid at `DS:1800`.** The stamp is
  art plus state; `0x08` accepts in some cells and refuses in others, and a BFS over it walks you into
  `INVALID MOVE!`.
- **A refusal needs a control that proves the actor can act.** Every "it did not move" in this session
  is worthless without the row where the same state moved onto a tile the rule does not touch.
- **`E` after a load is swallowed**; press it twice and confirm with `DS:4A`.

## 5. Hazards, each of which cost something tonight

- **Injecting keys into the `deploy/spice86-novnc` container crashes Spice86** —
  `InvalidOperationException: Collection was modified` in `CfgCpuViewModel.RegenerateGraphFromNodeAsync`,
  racing the pause `send_keyboard_key` causes. Memory reads are safe. When a human is driving, keep
  the host side read-only.
- **`--write-provenance` will not flip a verdict, only digits.** `cmd_D` said "never appears" while a
  capture showed 1, and the tool refused and said so. That line is a human edit; do not "fix" it by
  editing the number.
- **A multi-line `edit` whose `oldText` stops mid-sentence leaves the tail behind.** It happened twice
  here — once in `state.h` (an orphaned comment fragment after the closing `*/`, caught because the
  engine build reads the field back) and once in a `needs-gameplay` table row (a duplicated `| ... |`
  tail). Verify by reading the **specific text** back, not a line count.
- **`git add path/that/git-mv-already-staged` aborts the whole command** with a pathspec error, and a
  `git commit -F -` chained after `&&` can consume the next command's heredoc. One commit per call.
- **`captures/` is gitignored.** Every finding above also lives in an `asm/` header or a `docs/` page,
  in the same commit, per `AGENTS.md` § 3.
