`tools/cmd_handlers.py` reads each handler's `# provenance:` line to decide whether that handler

the column from `ExecutedInstructions` directly, keep the `# provenance:` line as prose context

### D10 — is the diagonal step a version difference?

The Adric cheat sheet gives separate routes for games "that do not allow diagonal movement" and
those that do. This project measured a diagonal at `asm/212e` and recorded it as simply how
creatures move. If diagonals are build-specific, that measurement is variant-specific and the
engine may be modelling the wrong build. Cheap to test: one capture on a sector where a creature

## 4. Facts worth knowing cold

**The in-game hint table.** `original/ultimaii.exe`, file `0x18xx..0x1990`, NUL-separated, seven
entries: `SOME FIGHTERS WEAR MAGIC HELMS!` / `AVIATORS USE SKULL KEYS!` / `SAYLORS WEAR BLUE
TASSLES!` / `MAGES CARRY WANDS OR STAFFS!` / `GUARDS CARRY KEYS!` / `ANKHS OPEN SPACE!` /
`PLANES NEED BRASS BUTTONS!`. This is the game's own text corroborating third-party walkthrough
claims, and it is the ground truth for re-cutting `asm/4C50`.

**`asm/20AB_bcd_price_from_stats` produces only:** `4, 8, 12, 20, 32, 52, 84, 136, 220, 356, 576,
932…` (a Fibonacci walk seeded 4,4, loop count `DI = (caller_AL+8+CF) − bitlength(int + [DS:4E])`).
Higher stats → shorter DI → **lower price**. The wiki's grocery maximum of **52 gp is the 6th value
in that sequence**, and at minimum stats (int=cha=0x10) a caller passing `AL=4` yields exactly
`0052`. Two independent third-party sources now agree with the direction. **The standing DOUBT is
not closed**: the tavern's observed `0200` is still unreproduced and 200 is not in the sequence —
but different callers pass different `AL` (`asm/17B2` passes 3), so comparing the tavern's number
against the grocery's expected 52 may have been a category error. `DS:4E` charisma-vs-wisdom is
still unsettled.

**Command dispatch, from the bytes.** `asm/0A1F_cmd_dispatch` is the only route to the 26 handlers:
`sbb $0x41,%al` → `add al,al` → `mov bx, cs:[si+0x0730]` → `jmp *bx`. The range test is in **two
pieces before it** (`cmp $0x41 / jae` at `asm/09FB`, `cmp $0x5a / jbe` at `asm/0A18`), so "not a
command letter" is a distinct outcome from "a handler that declined". Every handler ends in
`jmp L_000c33` (`cmd_done`: prints CR, then **falls through** to `asm/0A38_post_command_tail`, the
tail that runs the creature sweep). There is no `ret` in that path.

**`cmd_Y` does not return to the command loop.** Observed, not inferred: after `YELL WHAT?` every
later letter accumulated as text and never dispatched (run 1's log ended reading `M1CS*RT`). Its
fall-through into `asm/4551` is **not** `cmd_done`. `cmd_N` falls through into `asm/3BDD`
(`mov 0xe3,%al`) — also not `cmd_done`. Both are parked, and this is why leaving them unimplemented
was correct: an engine `cmd_Y` would have had to invent a return the bytes do not have.

**`cmd_J`'s message overstates its body.** `JUMP...WHEE...` with no jump and no tail-call hiding
one. Now observed.

**Marker gate.** `tools/cmd_marker_gate.py`, 15 controls, wired into `check_all.sh` and
`engine-tests.yml`. Five rules; the two that matter most: an unproven handler must carry its
`UNPROVEN: cmd_X` marker, and a **proven** handler must **not** (R2 — a stale marker is a lie in
the other direction, and it fired for real the day the capture landed). Completion claims are read
from the checkpoint table's **status cell** for **CP6 and CP8 only** — not from prose, and not from
unrelated checkpoints.

## 6. Hazards. Each of these cost minutes this session.

1. **The auto-PASS confounds any measurement taken across an idle gap.** Food falls ~10 per ~7.5 s
   window with no input at all. Bracket a single keypress with back-to-back reads, or raise
   `auto_pass_polls`. A first reading of "a blocked step costs 19 food" was this artefact.
2. **Always run the control before believing a delta.** Read the value three times with *no input*.
   That is what turned a confident wrong answer into a finding.
3. **Confirm the step landed** by reading `DS:00/01` before treating any per-step delta as a step
   cost. Six keypresses on the paralyzed seed moved nothing.
4. **Grep item names in singular AND plural.** Searching `SKULL KEY` found nothing; the binary says
   `AVIATORS USE SKULL KEYS!`. "Absent from my grep" is not "absent from the game".
5. **Do not trust the `exec` column as current.** It is a hand-kept copy; eight of 26 grades were
   wrong. Verify against `captures/` before making a claim about what has been observed.
6. **`cmd_handlers.py`'s "60 harvests" is a literal**, not a measurement. The corpus is 141.
7. **A gate that cannot see its input passes vacuously.** The marker gate reported "0 of 26
   implemented" over two real handlers because its definition regex matched only `void`/`int`/`bool`
   returns and the handlers returned an enum. That is the fifth such bug in this project. Write the
   red control first, every time.
8. **A gate that is red forever is as useless as one that cannot fail.** R4 initially counted every
   `done` in every checkpoint row, which would have made it red from the first handler written.
9. **A gate that reads prose will fire on its own rule text.** R4 first grepped the state doc for
   "code-complete" and fired on the sentence stating the rule.
10. **Never edit `asm/` bodies.** Only filenames and `#` comment lines change without a
    `body corrected:` marker; labels are body. Everything this session touched in `asm/` was header
    comments, and `assemble_clean.sh` stayed green.
11. **`str_out_audit.py --emit` writes the file itself** — do not redirect its stdout.
12. **Never put backticks in `git commit -m`**; use `-F` or a heredoc, and check the commit landed
    (one this session came out with the body as the subject line).
