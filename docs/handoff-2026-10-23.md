## Standing traps — read before trusting anything
Carried forward, plus today's. **Today's are marked NEW.**

* **Memory reads pause the CPU**; keys sent in that window are silently lost. Settle
  0.5–1 s after a read before injecting a key, and verify every step. Today this moved a
  monster between a read and a screenshot and produced an apparent rendering mismatch.
* **`monitor breakCsIp` parses hex while `/api/status` reports decimal.** `reject_trap.py`
  converts in one asserted place.
* **`ExecutedInstructions` is a deduplicated address set, not a trace.** `blocks` are
  *discovered*, not executed.
* **`DS:20` is scratch, not a reject signal.**
* **Never edit a file with a script; never heredoc a non-trivial script.** `str.replace`
  that misses returns the string unchanged and exits 0.
* **In `asm/`, only the filename and `#` lines may change — labels are body.** As of today
  the guard is `engine/tests/asm_body_guard.py`: it compares the whole tree's non-comment
  content, ordered by each file's start address, against HEAD. So **file boundaries may now
  move** (rename, merge, split) and body content still may not. Do not "fix" a merge by
  editing a label to match a new range — labels are still body.
* **A model that agrees with nothing but itself is not evidence.** `asm/20AB` was described
  three times in one day and was wrong twice: first `popcount` for a bit-length loop, then
  "multiply by repeated addition" for a Fibonacci walk, and the first simulator had `DAA`
  *subtracting* 6 instead of adding, which produced `01A6` where the answer is `0012`. Every
  version printed a confident number. Hand-check a simulator against one case you can compute
  before quoting any of it — and note the model still does not reproduce the observed `0200`.
* **A gate that blocks the work it exists to enable is itself the defect.** CP0 failed on any
  `asm/` deletion, which made the approved merges impossible and would have reported them as
  vandalism. The fix was to restate the invariant more precisely, not to relax it — the new
  check is strictly stronger. When a gate and a rule are in conflict, say so rather than
  working around either.
* **Demonstrate a gate failing before trusting it passing.** Every new checker here was
  perturbed and observed going red: `map_signs --selftest` (two ways),
  `dungeon_spawn_check` (formula perturbed), `strings_atlas --selftest` (failed for real,
  twice, during development), and `asm_body_guard` (one `das`→`daa`, and a removed file).
* **`pgrep`/`pkill -f` matches its own shell.** Kill by pid, or check ports.
* **Scratch goes to `/var/tmp`, never `/tmp`** (tmpfs here — it takes RAM from the model).
  Note `ctx_execute_file` resolves the workspace root differently and will refuse paths
  under `/var/home/...` for some files; use a script file for binary work.
* **NEW — an emulator breakpoint cannot be removed once armed.** `monitor help` lists
  `breakCsIp` but no removal command, so `bp_read.py --selftest` (which arms on the live
  address) **poisons the run**. One emulator run per capture target; restart between them.
* **NEW — `isPaused` is not proof of a breakpoint hit.** HTTP memory reads pause the CPU,
  and `spice86_type.py` reads memory to verify its own keys, so a concurrent key send
  causes real pauses at random addresses. Match the stop address against the request or
  you get genuine memory from the wrong moment — the worst kind of wrong answer.
* **NEW — `T,<direction>` queued at `--delay 0.02` does not reliably transact.** `T` alone
  prints `CMD: TRANSACT-PASS`, which proves the key arrives, but the paired version fell
  through to `CMD: PASS` repeatedly and the shop/food path never executed. The documented
  recipe came from a human-driven VNC session and does not reproduce headlessly. Treat
  "needs a talk" as **owner-needed**, not agent-doable, until the timing is understood.
* **NEW — `DS:4E` vs `DS:4F` (cha/wis) is still DISPUTED**, and every maxout character has
  them equal so no capture so far can separate them. Any claim of the form "this reads
  charisma" is really "this reads `[DS:4E]`, labelled charisma by `state.h`".
* **Probe maps must be installed before launch** (`spice86_start.sh --seed-map`).
* **The world wraps.** Start probe walks mid-map.
* **Enumerate `captures/spice86/` before running a new capture.** Today this saved a
  launch: the dungeon formula was checkable against two dumps already on disk.
* **Read the tool index in `docs/spice86-capture.md` before writing anything against a
  live session.**
* **`[DI+0x1B7]` is a kind index on the overworld and `slot>>1` in a dungeon.** Neither is
  a sprite. Trust the live dump, and read the spawner before naming a field.
* **A single area is not a sample.** Still true, and today it gained a variant: **a single
  agreeing sample is not a test either.** 776 agreeing cells could not answer which field
  the renderer reads; one disagreement did.
* **A capture directory name is not a fact about its contents.** `airport32` is a dungeon;
  `tower-34` is a tower. Classify by bytes, and `tools/dungeon_spawn_check.py` now does.
* **An "active slot" filter is a claim about the encoding.** NEW: so is a *scoring* filter.
  `monx_layout_scan` initially scored slots the file never authored and reported sector 20
  as a total layout failure when the file simply authors nothing. Absence and
  contradiction are different verdicts.
* **Do not upgrade an arithmetic fit into a mechanism.** NEW corollary: do not upgrade an
  idiom name into branch polarity. `cmc;sbb;das;cmc` ends with a complement that inverts
  the carry, so the following `jb` is the **success** path. Simulate it.
* **`view.h`'s two-step is not a bug.** NEW: and the open question was never the shift, it
  was the field. It reads the grid cell. See `docs/art-index.md`.
* **NEW — a shop needs an NPC standing at the sign.** `T` alone, or `T` with a stale
  direction buffer, prints `TRANSACT-PASS` and means nothing. Use
  `--keys T,Up --delay 0.02`, launch with `--patch-arrows`, and check
  `tools/shop_access.py` for where it is even possible.
* **NEW — the shop closes after one purchase.** A second item's keystrokes fall through to
  the command loop, where `3` is an illegal command and `y` is YELL. Re-open per item.
* **NEW — `u2_edit.py maxout` does not populate the armour table.** It sets `DS:62` to
  POWER while `DS:96+6` stays `00`. Either owned ≠ worn or the seeder is incomplete;
  unresolved, and it affects any capture that assumes a kitted character is fully kitted.

## Corrections made today, so nobody re-introduces them

* `commerce.md` § 3: "`DS:27/28` is a transient scratch write, not the price field" —
  **wrong**. It is the price operand; it is transient, which is a different claim.
* `commerce.md` § 3: "the transaction body is past the end of the file, so extend the
  range upward" — **wrong**. Three shared helpers with their own files. See
  `docs/g22-split-proposal.md`.
* `asm/20AB` / `commerce.md` § 3 / G23: "derives a loop count from `popcount(int + cha)`" —
  **wrong**. The shift loop `inc %si; clc; rcr $1,%al; or %al,%al; jne` counts **shifts to
  reach zero**, i.e. the bit length. All three places now say bit length.
* `asm/20AB`: "a BCD multiply by repeated addition" — **wrong**. Each pair takes the other's
  old value while the first receives the sum, so the pairs walk a Fibonacci sequence seeded
  4,4 (`4, 8, 12, 20, 32, 52, 84, ...`) and the result lands in `DS:27/28`, the printed and
  charged pair. Not a multiply, and not left in `DS:29/2A`.
* **Still open, not a correction:** the corrected model gives `0020` for the tavern call on a
  maxed character where the game printed `0200`. Same digits, transposed across the pair. Do
  not call `asm/20AB` "the price formula" until it reproduces a printed number.
* `commerce.md` § 3b (written today, corrected same day): `asm/2052`'s trailing `jb` is
  the **affordable** path, not the failure path.
* `monster-spawn.md` § 2: "`monxNN` is five parallel arrays" — **six**.
* `sector-rulesets.md` § 2: "dungeons are the only outlier" — **`{4,5}` are**.
* `place-names.md` § 2: "runs of 3+ tiles" — the tool always emitted 2+.
